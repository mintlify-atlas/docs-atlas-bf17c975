Koharu can translate through APIs that follow the OpenAI Chat Completions shape. That includes local servers such as LM Studio and hosted routers such as OpenRouter. This is separate from Koharu's built-in OpenAI, Gemini, Claude, and DeepSeek provider presets — it is a flexible slot for any endpoint that speaks the OpenAI API format.

## What Koharu expects from a compatible endpoint

In the current implementation, Koharu expects:

- a base URL that points at the API root, usually ending in `/v1`
- `GET /models` for connection testing
- `POST /chat/completions` for translation
- a response that includes `choices[0].message.content`
- bearer-token authentication when an API key is provided

Some implementation details matter:

- Koharu trims whitespace and a trailing slash from the base URL before appending `/models` or `/chat/completions`
- an empty API key is omitted entirely instead of sending an empty `Authorization` header
- a compatible model only appears in Koharu's LLM picker after both `Base URL` and `Model name` are filled in
- each configured preset shows up as its own selectable source in the LLM picker

<Note>
  API keys for compatible providers are stored securely in your system keychain instead of plain text config files. For headless or CI environments, see [Run Koharu in GUI, Headless, and MCP Modes](/how-to/run-gui-headless-and-mcp) for the `--no-keyring` option.
</Note>

## Where to configure it

Open **Settings** and scroll to **Local LLM & OpenAI Compatible Providers**. The current UI exposes:

- a preset selector: `Ollama`, `LM Studio`, `Preset 1`, `Preset 2`
- `Base URL`
- `API Key (optional)`
- `Model name`
- `Test Connection`
- advanced fields for `Temperature`, `Max tokens`, and a custom system prompt

`Test Connection` calls `/models` with a 5-second timeout and reports whether Koharu connected successfully, how many model IDs the endpoint returned, and the measured latency.

## Connect LM Studio

Use the built-in `LM Studio` preset when you want a local model server on the same machine.

<Steps>
  <Step title="Start LM Studio">
    Start LM Studio's local server from the LM Studio application.
  </Step>
  <Step title="Open Koharu Settings">
    Open **Settings** in Koharu and scroll to **Local LLM & OpenAI Compatible Providers**.
  </Step>
  <Step title="Select the LM Studio preset">
    Choose the `LM Studio` preset. The base URL defaults to `http://127.0.0.1:1234/v1`.
  </Step>
  <Step title="Set the model name">
    Enter the exact LM Studio model identifier in `Model name`. If you are unsure of the ID, query LM Studio directly:
    ```bash
    curl http://127.0.0.1:1234/v1/models
    ```
    Copy the `id` field for the model you want.
  </Step>
  <Step title="Test the connection">
    Leave `API Key` empty unless you configured authentication in front of LM Studio, then click `Test Connection`.
  </Step>
  <Step title="Select the model in the LLM picker">
    Open Koharu's LLM picker and select the LM Studio-backed model entry.
  </Step>
</Steps>

<Note>
  Koharu's connection test only shows the model count, not the full model names, so you still need to know the exact model ID you want to use.
</Note>

## Connect OpenRouter

Use `Preset 1` or `Preset 2` for hosted OpenAI-compatible services such as OpenRouter. That avoids overwriting the local LM Studio preset.

<Steps>
  <Step title="Create an API key">
    Create an API key in your OpenRouter account.
  </Step>
  <Step title="Open Koharu Settings">
    Open **Settings** in Koharu and scroll to **Local LLM & OpenAI Compatible Providers**.
  </Step>
  <Step title="Select a preset">
    Choose `Preset 1` or `Preset 2`.
  </Step>
  <Step title="Configure the endpoint">
    Set `Base URL` to `https://openrouter.ai/api/v1` and paste your OpenRouter API key into `API Key`.
  </Step>
  <Step title="Set the model name">
    Enter the exact OpenRouter model ID in `Model name`. OpenRouter model IDs should include the organization prefix, not just a display name.
  </Step>
  <Step title="Test and select">
    Click `Test Connection`, then select that preset-backed model from Koharu's LLM picker.
  </Step>
</Steps>

## Use multiple backends simultaneously

Koharu does not treat these endpoints as one generic remote bucket. Each configured preset becomes its own LLM entry source:

- `LM Studio` can point at a local server
- `Preset 1` can point at OpenRouter
- `Preset 2` can point at another self-hosted OpenAI-compatible API

That lets you keep multiple compatible backends configured and switch between them from the normal LLM picker.

## Other compatible endpoints

For other self-hosted or routed APIs, use the same checklist:

- use the API root as `Base URL`, not the full `/chat/completions` URL
- make sure the endpoint supports `GET /models`
- make sure it supports `POST /chat/completions`
- use the exact model `id`, not just a marketing name
- provide an API key if the server requires bearer authentication

<Warning>
  If the server only implements the `Responses` API or some custom schema, Koharu's current OpenAI-compatible integration will not work without an adapter or proxy, because Koharu currently talks to `chat/completions`.
</Warning>

## Common mistakes

- using a base URL without `/v1`
- pasting the full `/chat/completions` URL into `Base URL`
- leaving `Model name` empty and expecting the model to appear anyway
- using a display label instead of the exact API model ID
- assuming `Test Connection` loads or selects a model for you
- trying to use an endpoint that only supports the newer `Responses` API
