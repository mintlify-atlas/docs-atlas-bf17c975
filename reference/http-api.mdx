Koharu exposes a local HTTP API that the desktop UI and the headless Web UI both use. It is the same API you can call from scripts, automation tools, or custom integrations.

```text
http://127.0.0.1:<PORT>/api/v1
```

<Note>
  The server always binds to `127.0.0.1`. It is not reachable from other machines on your network. When no `--port` flag is provided, Koharu chooses a random local port on startup. Use `--port` to fix it.
</Note>

## Runtime model

- The API and the MCP server share the same loaded documents, models, and pipeline state as the GUI.
- Starting a pipeline job through the API is the same operation as clicking **Translate All** in the desktop app.
- When `--headless` is set, the same API is available — only the desktop window is skipped.

## Common response shapes

| Type | Fields |
|------|--------|
| `MetaInfo` | App version, active ML backend |
| `DocumentSummary` | Document id, name, size, revision, layer availability, text-block count |
| `DocumentDetail` | Full document metadata plus all text blocks |
| `JobState` | Current pipeline job progress |
| `LlmState` | Current LLM load state |
| `ImportResult` | Imported document count and summaries |
| `ExportResult` | Count of exported files |

## Meta and fonts

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/meta` | Get app version and active ML backend |
| `GET` | `/fonts` | List font families available for rendering |

## Documents

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/documents` | List loaded documents |
| `POST` | `/documents/import?mode=replace` | Replace the current document set with uploaded images |
| `POST` | `/documents/import?mode=append` | Append uploaded images to the current document set |
| `GET` | `/documents/{documentId}` | Get one document and all text-block metadata |
| `GET` | `/documents/{documentId}/thumbnail` | Get a thumbnail image |
| `GET` | `/documents/{documentId}/layers/{layer}` | Fetch one image layer |

The import endpoint uses `multipart/form-data` with repeated `files` fields.

Document layers available via `/layers/{layer}`:

| Layer | Description |
|-------|-------------|
| `original` | The source image as imported |
| `segment` | The segmentation mask generated by detection |
| `inpainted` | The image after text removal |
| `brush` | Manual brush paint layer |
| `rendered` | The final image with translated text |

## Page pipeline

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/documents/{documentId}/detect` | Detect text blocks and layout |
| `POST` | `/documents/{documentId}/ocr` | Run OCR on detected text blocks |
| `POST` | `/documents/{documentId}/inpaint` | Remove original text using the current mask |
| `POST` | `/documents/{documentId}/render` | Render translated text onto the page |
| `POST` | `/documents/{documentId}/translate` | Generate translations for one block or the full page |
| `PUT` | `/documents/{documentId}/mask-region` | Replace or update part of the segmentation mask |
| `PUT` | `/documents/{documentId}/brush-region` | Write a patch into the brush layer |
| `POST` | `/documents/{documentId}/inpaint-region` | Re-inpaint a rectangular region only |

Useful request details:

- `/render` accepts `textBlockId`, `shaderEffect`, `shaderStroke`, and `fontFamily`
- `/translate` accepts `textBlockId` and `language`
- `/mask-region` accepts `data` plus an optional `region`
- `/brush-region` accepts `data` plus a required `region`
- `/inpaint-region` accepts a rectangular `region`

## Text blocks

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/documents/{documentId}/text-blocks` | Create a new text block from `x`, `y`, `width`, `height` |
| `PATCH` | `/documents/{documentId}/text-blocks/{textBlockId}` | Patch text, translation, geometry, or style |
| `DELETE` | `/documents/{documentId}/text-blocks/{textBlockId}` | Remove a text block |

The `PATCH` endpoint accepts any combination of these fields:

<ParamField body="text" type="string">
  Raw OCR text for the block.
</ParamField>

<ParamField body="translation" type="string">
  Translated text to render onto the page.
</ParamField>

<ParamField body="x" type="number">
  Horizontal position in pixels.
</ParamField>

<ParamField body="y" type="number">
  Vertical position in pixels.
</ParamField>

<ParamField body="width" type="number">
  Block width in pixels.
</ParamField>

<ParamField body="height" type="number">
  Block height in pixels.
</ParamField>

<ParamField body="style" type="object">
  Style settings: font families, font size, RGBA color, text alignment, italic and bold flags, and stroke configuration.
</ParamField>

Patching a field that affects rendering automatically re-renders that block.

## Export

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/documents/{documentId}/export?layer=rendered` | Export one rendered image |
| `GET` | `/documents/{documentId}/export?layer=inpainted` | Export one inpainted image |
| `GET` | `/documents/{documentId}/export/psd` | Export one layered PSD file |
| `POST` | `/exports?layer=rendered` | Bulk export all rendered pages |
| `POST` | `/exports?layer=inpainted` | Bulk export all inpainted pages |

Single-document export endpoints return binary file content. Bulk export returns `ExportResult` with a count of files written.

The PSD export includes all available layers as separate Photoshop layers with editable text.

## LLM control

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/llm/catalog` | List the grouped local/provider LLM catalog |
| `GET` | `/llm` | Get the current LLM status |
| `PUT` | `/llm` | Load a local or provider-backed model |
| `DELETE` | `/llm` | Unload the current model |

`GET /llm/catalog` accepts an optional `language` query parameter.

`PUT /llm` request body:

<ParamField body="target" type="object" required>
  For a provider model: `{ "kind": "provider", "providerId": "openai", "modelId": "gpt-4o" }`

  For a local model: `{ "kind": "local", "modelId": "..." }`
</ParamField>

<ParamField body="options" type="object">
  Optional generation overrides: `temperature`, `maxTokens`, `customSystemPrompt`.
</ParamField>

## Provider and runtime configuration

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/config` | Read the current app config |
| `PUT` | `/config` | Write and reload the app config |

The config body includes:

- `data` — data path settings
- `http` — `connect_timeout`, `read_timeout`, `max_retries`
- `pipeline` — selected engine id for each pipeline stage
- `providers` — array of `{ id, base_url, api_key }` entries

<Note>
  Saved provider API keys are returned as `[REDACTED]` rather than raw secrets. Submitting `[REDACTED]` as a key value leaves the existing keyring entry unchanged. Submitting `null` or omitting the field clears it.
</Note>

Built-in provider ids: `openai`, `gemini`, `claude`, `deepseek`, `openai-compatible`.

## Jobs

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/jobs/pipeline` | Start a full processing job |
| `DELETE` | `/jobs/{jobId}` | Cancel a running pipeline job |

Pipeline job request fields:

<ParamField body="documentId" type="string">
  Target one page. Omit to process all loaded pages.
</ParamField>

<ParamField body="llm" type="object">
  LLM target and options: `{ target, options }`.
</ParamField>

<ParamField body="language" type="string">
  Target language for translation.
</ParamField>

<ParamField body="shaderEffect" type="string">
  Shader effect to apply when rendering text.
</ParamField>

<ParamField body="shaderStroke" type="boolean">
  Enable stroke effect on rendered text.
</ParamField>

<ParamField body="fontFamily" type="string">
  Font family to use when rendering text.
</ParamField>

## Events stream

Koharu exposes a server-sent event (SSE) stream for real-time state updates:

```text
GET /api/v1/events
```

The stream sends an initial `snapshot` event on connection and uses a 15-second keepalive.

| Event name | Triggered when |
|-----------|----------------|
| `snapshot` | Initial state on connection |
| `documents.changed` | The document list changes |
| `document.changed` | A single document's state changes |
| `job.changed` | A pipeline job's progress changes |
| `download.changed` | A download's state changes |
| `llm.changed` | The LLM load state changes |

## Typical workflow

The normal API sequence for translating one page:

<Steps>
  <Step title="Import the page">
    `POST /documents/import?mode=replace` — upload image files as multipart form data.
  </Step>
  <Step title="Detect text blocks">
    `POST /documents/{documentId}/detect` — runs the detector and segmenter engines.
  </Step>
  <Step title="Run OCR">
    `POST /documents/{documentId}/ocr` — extracts source text from each block.
  </Step>
  <Step title="Load an LLM">
    `PUT /llm` — load a local or provider-backed model for translation.
  </Step>
  <Step title="Translate">
    `POST /documents/{documentId}/translate` — generates translated text for all blocks.
  </Step>
  <Step title="Inpaint">
    `POST /documents/{documentId}/inpaint` — removes original text from the image.
  </Step>
  <Step title="Render">
    `POST /documents/{documentId}/render` — draws translated text onto the cleaned page.
  </Step>
  <Step title="Export">
    `GET /documents/{documentId}/export?layer=rendered` — download the final image.
  </Step>
</Steps>

For agent-oriented access instead of direct HTTP orchestration, see the [MCP Tools Reference](/reference/mcp-tools).
